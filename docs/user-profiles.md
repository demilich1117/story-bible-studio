# 制作你在故事里扮演的角色

**用户档案（User Profile）保存的是你想在故事里扮演的人物。** 它可以包含身份、经历、性格、说话方式、与其他人物的起始关系，以及几种可选择的开场。

例如，同一个城市设定下，你可以分别制作“外地送信人”和“本地店主”两份档案，用不同身份开始各自的故事。作品中的世界与主要人物保存在 Story Bible 中，你扮演的角色保存在用户档案中，实际发生的剧情保存在具体会话中。

## 项目已经提供了哪些东西？

已有流程包括：从讨论或原稿整理人物资料、导入档案、保留修订版本、检查格式、列出开场，以及在新会话中绑定档案。

现有格式模板位于 [User Profile 导入与绑定](../.agents/skills/story-bible-studio/references/profile-imports.md)：

- `sections` 示例：把简短内容直接写在 JSON 中。
- `section_files` 示例：用 JSON 指向五篇独立 Markdown，适合持续讨论和修改。

目前没有单独的 `profile new` 命令，也没有网页档案创建向导。**由 Agent 和你一起完成构筑，再用现有导入命令建档；网页负责选择建好的档案。** 下方提供可直接发给 Agent 的提示，以及一个可选的构思提纲。

## 1. 先选好作品，把这段话发给 Agent

先让 Agent 打开项目文件夹，确认已经创建了要使用的作品。把下面的作品名和想法换成自己的；想法还很少也可以开始。

```text
请按 Story Bible Studio 的现有流程，帮我从零构筑一个用户角色档案。
作品名称：【填已有作品名称】
我的想法：【例如：我想扮演一个初来乍到的送信人，其余还没想好】

请先阅读项目 AGENTS.md、.agents/skills/story-bible-studio/SKILL.md，
以及 .agents/skills/story-bible-studio/references/profile-imports.md 和必要的构筑说明。
请使用本项目 .venv-workbench 中的 Python 执行命令。

先了解这个作品已经确定的世界与主要人物，再和我讨论角色身份、性格、
起始关系、说话方式和开场。重要方向给我少量选择，其余细节成组补全；
保存已经确认的内容，不要反复问同样的问题。

请把内容整理为角色、关系接口、亲密设定、语料和开场候选五部分。
没有已确认的亲密设定时明确写“有意留白”。说话方式根据人设在构筑时补全。
首次草稿放在作品的 素材/Profile草稿/<档案ID>/ 中。

我确认后，请生成 section_files 格式的导入 JSON，用 profile import 正式建档，
再执行 profile validate，并列出可选开场。与已有设定冲突的内容先指出并解决。
完成后告诉我档案名称、保存位置，以及如何绑定到新会话；等我选好再开始故事。
```

如果已有一份人设笔记，把它提供给 Agent，并将“从零构筑”改成“整理并导入我提供的人设”。原稿不需要事先改成 JSON，格式转换由 Agent 完成。

## 2. 可选：先填一点构思提纲

这份提纲帮助你表达想法，**不是可以直接导入的档案文件**。不用全部填满，没想好的地方可以写“请给我几个建议”，之后再和 Agent 讨论。

```text
所属作品：
想扮演的人物姓名或称呼：
年龄、身份与日常生活：
外貌或容易被记住的特征：
最想达成的事：
性格、习惯与弱点：
与已有主要人物怎样认识，目前是什么关系：
平时怎样说话，遇到熟人或紧张时有什么变化：
想从什么场景开始：
亲密相关设定：有意留白 / 另行讨论
其他一定要保留的想法：
```

Agent 最终会整理为五个文件：

| 文件 | 用普通话说，它写什么 |
| --- | --- |
| `角色.md` | 我是谁，经历过什么，外貌和性格怎样，想做什么。 |
| `关系接口.md` | 我与作品中已有的人物怎样认识，故事开始时是什么关系。 |
| `NSFW.md` | 已确认的亲密相关设定；没有这部分内容时写“有意留白”。 |
| `语料.md` | 我怎样说话，对不同的人、在不同场景中有什么区别。 |
| `开场候选.md` | 可以从哪些地方、哪些事件开始，由我选一个。 |

## 3. 在工作台中使用档案

Agent 导入并验证成功后：

1. 刷新工作台的“会话阅读”页面，在左侧选中所属作品。
2. 点击“会话卡座”旁的 **“＋ 新建”**，填写会话名称。
3. 在 **“用户角色 Profile”** 中选择刚做好的档案。
4. 选择一个开场，或保留 **“空白开始”**，然后点 **“创建会话”**。
5. 在输入框写下回应或开场要求，用 **“复制续玩指令”** 交给 AI 助手继续。

也可以直接告诉 Agent：“请用这份档案和我选定的开场创建一个新会话。”让它使用项目的会话命令完成绑定。

如果下拉框中没有档案，先确认选中了正确作品，再让 Agent 检查导入与验证结果；有尚未处理的设定冲突时，档案会处于待审核状态，暂时无法用于新会话。

## 4. 以后怎样修改？

把想改的内容告诉 Agent，例如：“保留这个角色的经历，但把说话习惯改得更直接一些。”Agent 会基于同一个档案 ID 更新材料，生成待确认版本和差异，审阅后再应用。

**每个会话使用创建时绑定的档案版本。** 修改档案后，新会话可以选择新版；已经开始的会话继续使用原版，以保留当时的人物与剧情条件。想试新版角色时，新建会话即可。

## 给 Agent：落实到现有文件和命令

以下是操作细节，普通用户可以交给 Agent 处理。以 [profile-imports.md](../.agents/skills/story-bible-studio/references/profile-imports.md) 和当前 CLI 帮助为准。

### 草稿与正式档案放在哪里

首次草稿建议放在作品内的 `素材/Profile草稿/<档案ID>/`，与最终的 `用户档案/<档案ID>/` 分开。**首次导入前，不要预先在最终档案目录里放草稿。** 导入工具会根据该目录是否已存在判断首次导入或重导，正式目录应由工具生成。

例如，草稿目录中可以保存 `导入.json`，并把五篇 Markdown 放入同目录下的 `草稿/`。导入描述的结构沿用已有模板：

```json
{
  "schema_version": 1,
  "profile_id": "my-role",
  "display_name": "角色显示名",
  "aliases": [],
  "anchors": ["已存在的正史角色名"],
  "section_files": {
    "角色": "草稿/角色.md",
    "关系接口": "草稿/关系接口.md",
    "NSFW": "草稿/NSFW.md",
    "语料": "草稿/语料.md",
    "开场候选": "草稿/开场候选.md"
  },
  "conflicts": []
}
```

这是结构模板，使用时须填写实际姓名、关联角色，并完成五篇内容文件。`section_files` 中的路径相对于 `导入.json` 所在目录解析。正式导入会固化这些内容，之后改变草稿不会自行改变已导入的档案。

### 导入前需要补齐什么

- `关系接口.md` 按实际正史角色分块，例如 `## 人物名称`。角色自身设定与公共世界事实分别归档。
- `NSFW.md` 要有正文；没有已确认内容时，可以写“有意留白。”，不能只有标题。
- `语料.md` 必须有 `## 核心声线`、至少一节 `## 对象覆盖：对象名` 和至少一节 `## 场景覆盖：场景名`。根据确认的人设完成说话机制与少量校准例句，不等待会话采样，不用其他会话正文反推。
- `开场候选.md` 推荐使用 `## opening-01｜开场标题`，不同候选使用不同 ID。只有用户选定并创建会话后，开场才进入该会话。
- Agent 负责对照既有世界与人物判断冲突，CLI 不会自动理解并判断设定矛盾。未解决冲突写入 `conflicts`，不覆盖共享正史；有冲突的档案不能绑定新会话。

### 使用已有 CLI 完成建档和绑定

以下 PowerShell 示例在项目根目录执行；先把“你的作品”和档案名称换成实际值。

```powershell
$profilePython = '.\.venv-workbench\Scripts\python.exe'
$profileCli = '.agents/skills/story-bible-studio/scripts/story_studio.py'
$profileProject = '作品/你的作品'
$profilePayload = '作品/你的作品/素材/Profile草稿/my-role/导入.json'

& $profilePython -B $profileCli profile import --project $profileProject --payload $profilePayload
& $profilePython -B $profileCli profile validate --project $profileProject --id my-role
& $profilePython -B $profileCli profile openings --project $profileProject --id my-role
```

检查每条命令的结果，再决定下一步。首次建档无需虚构原稿附件，`--source` 可以省略。

用户选择了档案和开场后，再创建会话；`opening-01` 必须是上一步实际列出的候选。空白开始时省略 `--opening`。

```powershell
& $profilePython -B $profileCli session new --project $profileProject --id '新的会话名' --profile my-role --opening opening-01
```

已有 ID 的材料修改后再次导入，会生成待确认版本，当前档案继续有效。先审阅工具返回的差异，再用其返回的真实 revision 执行 `profile apply --project <项目> --id <ID> --revision <revision>`，随后验证。不得编造 revision 或手工改写档案版本记录。

首次导入包含冲突时，结果保存在导入记录中并标为待审核；已有 ID 的重导才会生成 `待确认/<revision>/` 和差异报告。这两种情况应分别处理。
