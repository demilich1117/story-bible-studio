# 文风：配置、机制与复核

文风控制表达选择，不负责发明世界、人物动机或剧情。日常先选择套装，再将用户自然语言微调转成维度覆盖。规则的唯一来源是 [style-presets.json](style-presets.json)；用 `style list` 查看套装，用 `style show` 读取当前真正生效的完整机制，不凭名称猜规则，也不在此另存一套预设定义。

库顶层 `preamble` 存放全局前置要求（如标点禁忌），渲染在有效规则最前、语域与各维度之前。它不属于保存的套装规则，不参与指纹、覆盖与继承，不能被 `rules` 覆盖；修改后对所有配置立即生效，包括旧式未结构化配置（在其保留提示后追加前置行）。

## 三层分工

- **语言语域**：语法、词汇、称谓和礼貌表达；现代自然汉语、西幻、中式古典。题材不自动触发某种语域，世界内爵位与角色的特别声线不能直接推广成旁白腔。
- **叙述机制**：节奏、叙述距离、细节取舍、修辞、对白呈现。每个维度说明适用情境、优先写法、典型偏差和例外；条件供主 Agent 按场景判断，不以关键词自动切换。
- **人物声线**：沿用固定人设的表达策略、对象覆盖与场景覆盖。旁白规则不能抹平人物差异。仪式、引用或特定角色的特殊表达只在适用范围生效。

叙述距离不扩大既有 POV 的知情权限，文风也不决定情节强度、关系进展或正文长度。本轮明确要求优先，其后是会话／单篇覆盖、项目配置和默认机制。视角、事实、人物声线与文风各管其适用范围。

## 选择与微调

统一入口 `python -B .agents/skills/story-bible-studio/scripts/story_studio.py`，下文省略。

```text
style list
style show --project <项目> [--session <会话>]
style set --project <项目> --preset 西式奇幻
style set --project <项目> --session <会话> --preset 西式奇幻
style set --project <项目> --session <会话> --inherit
```

项目设置写入 `项目配置.yaml` 的 `writing_style`，会话设置固定文风。`--inherit` 改为跟随当前项目，不升级正史。新项目保存完整自然叙事规则，新会话使用 `style: {mode: inherit}`。

自然语言微调由主 Agent 转成 YAML 或 JSON 请求，用 `style set --profile-file <文件>` 持久保存。只改变用户点名的维度，每项覆盖必须包含四个字段；写一个完整的新机制，不在旧指令后追加矛盾补丁。例如“熟人对白随意些”：

```yaml
rules:
  dialogue:
    when: 熟人私下交谈
    prefer: 按各自声线直接回应眼前事项，允许省略彼此已知的信息。
    avoid: 为表示随意而添加网络热词，或把不同人物写成相同短句口气。
    exceptions: 公开发言、陌生人和正式请求仍按人物身份与关系处理。
```

请求只接受 `preset`、`register`、`rules`。`rules` 可覆盖 `register/rhythm/distance/detail/rhetoric/dialogue`，每项包含 `when/prefer/avoid/exceptions` 非空字符串。`register` 顶层字段选择三种内置语域。指定 `preset` 会先重置全部机制，再应用本次覆盖；不指定则基于当前机制替换所列维度。撤销局部修改时通过 `style show` 查明来源后恢复该维度；重新选套装会清除全部微调。

例句只作说明，不是运行配置字段。未知预设、额外字段、残缺规则会报错。旧自定义字符串无法推导结构时须明确选择预设，不自动猜测。

## 本轮、单篇与旧配置

- 本轮临时要求用 `turn prepare --style-file <请求文件>`；覆盖保存在本次事务中，提交后下轮恢复持久文风。用户未说明时，本轮措辞请求只作用本轮；明确说“以后／默认／这个会话”才持久设置。
- 正式章节与片段开写前用 `style show --project <项目> [--style-file <单篇请求>]` 读取 `rules_text`，不指定会话。单篇请求随作者态素材保存，不借用 RP 动态资料。
- 新格式保存套装来源与完整规则，规则库升级不改变已保存效果；显式重新应用套装才采用新版规则。
- 旧 `style: inherit` 字符串仍继承绑定正史的 `default_style`；其他旧字符串沿用原值，报告标为尚未结构化。仅给项目添加 `writing_style` 不改变这些旧会话。选定会话后用 `style set --inherit` 或明确预设接入。
- 旧项目若没有 `writing_style`，新式继承仍会报告其旧项目默认值尚未结构化；在该项目显式 `style set` 后获得完整规则。旧字段继续用于旧会话兼容，不与新字段同步改写。

## 运行与偏差处理

RP 的每份新格式 ready 上下文自动含一份“有效文风规则”；旧式未结构化配置同样注入，此时内容为旧式保留提示加全局前置要求。完整规则计入必需材料预算，不能因预算紧张而静默排除。来源、指纹及旧格式提醒在检索报告中；不要将它们抄进正文、状态或记忆。

写前按当前场景采用规则的适用分支；转场允许节奏自然改变，不自动切换基础文风。写后在现有冷复核中检查语域漂移、旁白侵入对白、人物趋同、机械重复、修辞过量，只改命中的句段。不要新增逐项分析长文，不输出或保存私有决策卡。

近期原文、例句和摘要是连续性材料，不能替换配置或训练成永久文风。用户纠正后修正文或使用变体；文风修改不自动重写人物声线、正史和已提交剧情。

prepare 固定有效规则与实际依赖。起草期间依赖变化，commit 保留草稿并拒绝陈旧提交；先将草稿移存本会话临时工作文件，再 prepare、依据新规则复核并提交，不删除待审草稿。已经写入事件但渲染中断的提交继续走幂等恢复，不因后来改风格而另写一轮。

## 验收边界

自动测试验证解析、继承、快照与提交一致性，不能证明文学质量。正文验收须使用预设未附例句的新情境：观察语域是否合适、人物是否区分、转场是否适应、表达机制能否迁移、事实是否保持，并记录具体句段。禁词数量、固定句长和对白比例不能代替这些判断。集中试写采用临时中性项目；不修改真实作品，也不把试写当成人设证据。
