# 故事创作流程

## 开写前

先运行 `config --project <项目> --writing --show [--config-file <单篇覆盖>]`，读取有效输出值与 rules，规则见 [output-settings.md](output-settings.md)。持续修改写入 writing_defaults，单篇覆盖不影响后续；不指定 RP 会话。人称仅作用已明确的 user 角色，没有此角色时不改变整篇叙述者。双语仅限对白。

确定作品、正文类型和连续性来源：

- `故事/章节/`：正式长篇顺序内容。
- `故事/片段/`：可稍后编排的正式素材。
- 会话整理稿：从选定的角色扮演版本提炼，去掉状态栏和元说明。

按需读取相关 Story Bible 条目、明确指定的章节或片段、前一章节尾部。开写前运行 `style show --project <项目> [--style-file <单篇覆盖>]`，使用返回的 `rules_text` 作为有效文风；不指定会话，不凭名称猜规则。旧式未结构化配置沿用原意，显式调整时按 styles.md 接入。不得因为关键词相同就读取角色扮演会话；从会话整理成文时只读取用户明确指定的会话。需求明确时直接输出完整正文。

有独立人物语料时，只读取当前出场角色的核心声线和本场最相关覆盖块。例句用于校准节奏，默认改写；不要为了证明“像这个角色”而重复口头禅。回环梗在章节内同样遵守低频原则：连续场景不用，同一场景至多一次，只有产生新作用时才返场。

写正文前轻量检查用户意图、人物一致性和自然停点；用户纠正、明显漂移或复杂转场时，按 [turn-thinking.md](turn-thinking.md) 使用相关诊断项或完整决策卡。

## 成文原则

- 正文字数目标服从单篇覆盖、项目 writing_defaults.prose；旧项目无写作字数配置时回退 session_defaults.prose，最终默认 1000–1200。默认大致接近即可，不为轻微偏差反复改写；用户明确要求严格字数时例外。双语源语言对白不重复占用中文阅读目标。
- 让人物通过选择、动作、语气和回避显露设定，避免说明书式倾倒。
- 每个段落至少承担推进、揭示、转折、气氛或感官定位中的一种功能。
- 对话保持人物差异；动作必须在空间和因果上可连续复现。
- 抽象判断尽量落回可见动作、具体物件、生理反应或环境变化。
- 不因维护设定而牺牲场景节奏；只加载当前场景真正相关的事实。
- 不把后台约束、资料摘要或状态维护语言转成角色对白。人物提到医学、法律、职业或技术事项时，先按其知识、情绪和说话习惯处理；只有用户要求或情节依赖精确机制时才研究。

## 完成后

复核：人物动机、真正影响剧情的信息知情范围、时间地点、动作位置、衣物物品、伤势能力、线索承诺、结尾推动力。时间按 `resolved_time_display` 写成明确纪年、日期和时刻；相对时间只作补充。中国古代或中式架空题材先写世界内纪时，再附现代钟点换算，不换算现代年月日或星期。现代题材直接写现代时间；西幻及其他历法只写世界内时间，不附现代等值。

正式章节和片段不共享角色扮演会话状态，也不自动回写冻结的 Story Bible。需要维护长篇连续性时，在相邻章节或显式指定的作者态资料中维护，不建立隐式时间线层。

普通场景结束仅核对受影响的连续性。章节定稿、结构变更或明确里程碑时运行完整验证，再用 `milestone` 仅提交当前作品路径。检测到已有暂存内容时保留创作文件但跳过提交。会话分支不自动创建 Git 分支。
