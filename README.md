# Story Bible Studio

**一个配合 AI 使用的本地故事创作工作台，帮助你从一个点子开始，逐步搭建设定、写故事、进行角色扮演，并保存每次创作的进度。**

Story Bible 可以理解为“故事设定集”：把人物是谁、彼此有什么关系、世界怎样运转、哪些事情已经确定，整理成可以持续查阅的资料。写长篇、隔几天继续创作，或尝试另一条剧情时，这些资料能帮助你和 AI 接着往下写。

你可以在浏览器工作台输入想法，选择本机 Codex 或 OpenCode 直接生成，也可以继续在 AI 助手里讨论和创作。人物、设定和已保存的故事都放在电脑上的项目文件夹里。

## 可以用它做什么？

- **从零构思故事**：只有“想写一座下雨的城市”这样的点子也可以开始。和 AI 一起确定主角、人物关系、世界规则和故事方向。
- **整理已有设定**：把零散笔记交给 AI，按人物、世界、关系等主题整理；在导图里查看讨论过程、采用的想法和待解决的问题。
- **持续写作或角色扮演**：围绕同一个作品接着写，保留正文、当前场景、人物状态和剧情记忆。你也可以指定自己扮演的角色。
- **调整写法、尝试分支**：设置人称、大致字数、文风和创作要求；对最新回复生成另一个版本，或从保存的检查点开启另一条剧情。

## 先了解它怎样工作

工作台负责输入与阅读，AI 助手负责生成和保存：

| 在哪里 | 做什么 |
| --- | --- |
| **AI 助手**，例如 Codex、OpenCode、Antigravity | 和你讨论设定、生成故事，并按项目规则把结果保存到文件。需要能够读写本地项目文件、执行 Python 命令。 |
| **浏览器工作台** | 查看设定导图、阅读故事、选择会话、修改要求；直接发送给本地 Codex / OpenCode，或复制指令交给其他 AI 助手。 |

输入区的“生成方式”决定如何交给 AI：选择本地生成可直接发送；默认的“复制小票”会生成一段指令，需要粘贴给能访问项目的 AI 助手。模型和账号由所选平台提供，具体设置见下面的日常创作步骤。

下面按 Windows 的操作方式，从下载开始走一遍。暂时不需要了解 Git、MCP 或项目内部的命令。

## 第一次使用

### 让 Agent 帮你准备（推荐）

如果你已经有能操作本地文件、运行命令的 AI 助手，可以先打开一个用来放项目的文件夹，把下面整段话发给它。**还没下载项目也可以用这段指令。** 这里的 Agent 就是你正在使用的这类 AI 助手。

```text
我没有编程基础，请帮我在这台电脑上准备并启动 Story Bible Studio。
项目地址：https://github.com/demilich1117/story-bible-studio

如果当前目录已经是这个项目，就使用现有目录；否则请在当前可写目录中新建
独立文件夹，下载并解压项目，或使用已有的 Git 克隆它，保留已有文件。
可用 Git 且目标目录不存在时，可以执行：
git clone https://github.com/demilich1117/story-bible-studio.git story-bible-studio
然后进入下载好的项目目录；没有 Git 时，使用仓库的 Download ZIP。
请先阅读项目的 README.md、AGENTS.md 和 docs/agent-setup.md，
按初始化指南实际完成操作，不要只给我一串需要自己执行的命令。

请检查 Python 3.11+，准备项目专用的 .venv-workbench 环境，安装基础依赖，
验证程序可以运行，然后启动本地工作台、检查页面并告诉我访问地址。
如果缺少 Python，请通过官方渠道帮助安装；只有遇到必须由我点击的安装窗口、
权限或登录步骤时，告诉我具体需要做哪一步。

本次先完成基础安装和启动。请保留已有作品、会话和平台配置。
后续执行项目命令时，使用本项目虚拟环境中的 Python。
完成后告诉我：项目放在哪里、怎样再次启动，以及怎样让你创建第一个作品。
```

助手完成准备后，可以直接从下面的 **第 4 步“让 AI 帮你创建第一个作品”** 开始。第 1～3 步保留给希望自己安装的人。初始化的详细操作约定见 [Agent 初始化指南](docs/agent-setup.md)。

### 1. 下载并解压项目

点击 **[下载项目 ZIP](https://github.com/demilich1117/story-bible-studio/archive/refs/heads/main.zip)**，下载后右键压缩包，选择“全部解压缩”。也可以在仓库页面点击绿色的 **Code → Download ZIP**。

打开解压后的文件夹，直到能同时看到这些文件：

- `README.md`：你正在读的说明。
- `AGENTS.md`：给 AI 助手的项目规则。
- `启动工作台.cmd`：双击后启动网页工作台。
- `requirements.txt`：程序需要安装的依赖清单。

**这个文件夹就是后面所说的“项目文件夹”。** 请先完成解压，再运行其中的文件。

### 2. 安装运行环境

需要 **Python 3.11 或更高版本**。如果还没有安装，请从 [Python 官网](https://www.python.org/downloads/)下载适合 Windows 的正式版本，按安装程序提示完成安装。

回到项目文件夹，点击资源管理器顶部的地址栏，输入 `powershell`，按回车。会打开一个已经位于此文件夹的命令窗口。

先复制下面这一行，按回车，检查 Python 是否可用：

```powershell
python --version
```

看到 `Python 3.11.x` 或更高版本后，**依次执行**下面两行。第一行创建本项目专用的运行环境，第二行安装依赖；安装依赖时需要联网。

```powershell
python -m venv .venv-workbench
.\.venv-workbench\Scripts\python.exe -m pip install -r requirements.txt
```

命令执行结束、没有报错，就可以继续。以后日常打开工作台不需要重复安装。

### 3. 打开工作台

双击项目文件夹里的 **`启动工作台.cmd`**。如果准备使用 Codex 直接生成，改用 **`启动Codex工作台.cmd`**：它会寻找本机 CLI，并在尚未登录时引导授权。两个入口都需要先完成上面的 Python 和依赖安装。

启动成功后，浏览器会打开工作台，你会看到“设定构筑”、作品选择框和故事阅读页面。

首次打开还没有作品，这是正常的。下一步会创建你的第一个作品。

启动时出现的命令窗口需要保持运行，可以最小化。用完后，点击网页左下角的“关闭本地后台”。

### 4. 让 AI 帮你创建第一个作品

在你使用的 AI 助手中，把刚才的**项目文件夹作为工作目录打开**。选择的文件夹应当包含 `AGENTS.md`；只在普通网页聊天框里粘贴这段说明，无法让助手直接保存本地文件。

可以把下面这段话直接发给助手，作品名称和题材都可以换成你自己的：

```text
请先阅读项目根目录的 AGENTS.md，以及
.agents/skills/story-bible-studio/SKILL.md，按这个项目的流程帮助我创作。
运行项目命令时，请使用本项目的 .venv-workbench/Scripts/python.exe。

请新建一个叫《雨城来信》的作品。
我想写一名修表师在雨夜收到陌生来信的悬疑故事。
我还没有完整设定，请先和我讨论主角、城市和故事方向。
每次帮我梳理少量关键选择，并保存已经确认的设定和讨论进度。
先不要开始写正文。
```

跟着助手的提问继续聊就可以。它创建并保存作品后，项目文件夹中会出现 `作品/雨城来信/`。刷新工作台，在作品选择框里选中它。

点击顶部的 **“设定构筑”**，就可以查看已保存的主题与讨论。选择主题、填写新想法后，按下面的“生成方式”说明设置，再点“继续头脑风暴”。

### 5. 从设定进入第一段故事

等你觉得设定可以开始用了，可以对 AI 助手说：

```text
《雨城来信》的方向已经确定了。
请检查还有哪些设定会影响开写；如果没有阻碍，就保存可用于创作的设定版本，
新建名为“序章”的会话，从修表师收到那封信开始写第一段，并保存结果。
使用第三人称，字数大约 800 字，结尾留一个可以继续发展的线索。
```

助手完成保存后，回到工作台的 **“会话阅读”** 页面并刷新，在左侧选择作品和“序章”，即可阅读正文。

这里的“会话”指这个作品中的一条连续故事或一次角色扮演进程。一个作品可以有多个会话，分别保存各自的剧情进度。

## 想扮演自己的角色？先做一份用户档案

**用户档案（User Profile）就是“我在故事里扮演谁”的设定。** 例如，你可以扮演一名来到雨城的送信人，设定自己的身份、性格、说话习惯，以及与修表师的初始关系。

项目已有这套档案格式和制作流程，支持从零讨论，也支持整理已有的人设。你可以把下面这段话发给打开了项目文件夹的 AI 助手：

```text
请阅读 AGENTS.md、项目技能和 docs/user-profiles.md，
使用项目虚拟环境中的 Python，帮我为《雨城来信》构筑一份用户档案。
我想扮演一名刚来到这座城市的送信人，其他细节还没想好。

请按现有的 User Profile 流程，和我讨论身份、性格、与主要人物的起始关系、
说话方式和开场选择。重要方向让我选，其余细节给出成组建议并保存草稿。
在我确认内容后，整理成可导入的档案，执行导入和验证。
这次先完成档案；等我选择开场后，再把它绑定到一个新会话。
```

档案准备好后，刷新工作台，选择作品，点击左侧 **“＋ 新建”**。在弹窗的 **“用户角色 Profile”** 中选择档案，再选开场或“空白开始”，点击“创建会话”。

详细步骤、可填写的构思模板和给 Agent 的格式说明见 [用户档案制作指南](docs/user-profiles.md)。如果只是一起写故事，也可以使用“不绑定 Profile”的会话。

## 以后怎样继续创作？

每次使用时，双击 `启动工作台.cmd`；使用 Codex 直接生成时可用 `启动Codex工作台.cmd`。

### 选择生成方式

构筑和会话输入区都有“生成方式”，按需选择：

| 生成方式 | 怎样使用 |
| --- | --- |
| **Codex / OpenCode · 本地生成** | 本机需安装并登录对应 CLI。点击“检查生成连接”，选择主模型；Codex 还可选择推理强度。保留默认选项则沿用平台配置。 |
| **复制小票** | 让 AI 助手打开这个项目文件夹，将生成的指令粘贴给它。适合在已有聊天中继续，或使用其他平台。 |
| **OpenCode · 共享后台** | 希望在连接同一服务的 OpenCode 桌面端查找生成会话时使用，先按[共享后台说明](workbench/README.md#opencode--共享后台)配置。 |

桌面端登录与 CLI 登录需要分别确认；本地生成也不会自动显示到已有桌面聊天中。连接与模型设置的详细说明见[直接生成指南](workbench/README.md#直接生成构筑与续玩共用)。

### 接着写下一段

1. 在工作台左侧选择作品和会话，先看看上次写到哪里。
2. 在正文下方输入下一步想发生的事，或者你所扮演角色的回应。例如：“她先检查信封上的邮戳，没有马上拆信。”
3. 本地生成时点击 **“发送续玩”**；选择“复制小票”时，点击 **“复制续玩指令”**，再粘贴到 AI 助手里发送。
4. 等助手完成创作并保存。工作台会检测新内容；如果你正在阅读旧段落，点击“有新内容”提示查看即可。

界面中的“故事小票”就是这段交接指令，它带有作品、会话和本次要求。换一个新的 AI 聊天任务时，也可以用它让助手接手指定会话。

常见操作可以这样找：

| 你想做什么 | 操作方式 |
| --- | --- |
| 修改人物、世界或某个设定 | 打开“设定构筑”，选择主题，输入想法，点“继续头脑风暴”或“提出修订”；复制模式下再把指令交给 AI。 |
| 调整人称、大致字数或状态栏 | 在会话阅读页右侧修改设置并保存；窄屏下先打开“本桌菜单”。 |
| 告诉 AI 持续遵守某种写法 | 在右侧“本会话创作要求”中添加要求并保存，例如“对话简短一些”。 |
| 让最新一段换一种写法 | 写清改写要求，点“重生成”；复制模式下点“复制重生成指令”并交给 AI。完成后查看候选，再选择采用的版本。 |
| 从某个位置尝试另一种发展 | 先点“留个书签”保存检查点，再用“故事分支”创建新的会话。 |
| 生成中断，想接着完成 | 直接生成可按提示“重试原任务”，也可复制“恢复指令”交给 AI；其他恢复操作见[工作台说明](workbench/README.md#中断与恢复)。 |

## 故事保存在哪里？

你的作品会保存在项目文件夹中的 `作品/` 下。主要目录可以这样理解：

| 目录 | 内容 |
| --- | --- |
| `作品/作品名/StoryBible/` | 人物、世界、关系等设定资料。 |
| `作品/作品名/构筑/` | 构思过程、确认过的方向和讨论记录。 |
| `作品/作品名/用户档案/` | 你扮演的角色设定、开场候选与档案版本。 |
| `作品/作品名/会话/` | 各个会话的正文记录、当前场景、状态和记忆。 |
| `作品/作品名/故事/` | 按创作流程整理的章节与片段。 |

已保存的设定和故事可以用文本编辑器查看。需要修改时，可以告诉 AI 助手，让它按项目流程更新。

备份时，关闭工作台并等 AI 完成当前操作，再复制整个项目文件夹即可。浏览器输入框里尚未交给 AI 保存的草稿，以及字体、主题等阅读偏好，保存在当前浏览器里。

## 常见问题

### 输入 `python --version` 后没有显示版本

安装 Python 后，先关闭并重新打开 PowerShell。如果仍然找不到命令，可以试试 `py --version`；若它能显示正确版本，把创建环境的命令换成 `py -m venv .venv-workbench`，后面的安装命令保持不变。

### 安装时提示找不到 `requirements.txt`

通常是命令窗口没有打开在项目文件夹中。回到能看到 `requirements.txt` 和 `启动工作台.cmd` 的那一层文件夹，在地址栏输入 `powershell`，再执行安装命令。

### 双击启动后报错，或者浏览器没有自动打开

先查看启动时出现的命令窗口。提示缺少 Python 或 `yaml` 时，重新检查上面的运行环境安装步骤。如果后台已经启动，手动打开窗口中显示的网址即可；默认是 `http://127.0.0.1:8765`，端口被占用时会改用其他端口。

### 点了“复制续玩指令”，为什么没有新故事？

还需要把复制的指令发送给能访问此项目文件夹的 AI 助手。助手生成内容并完成保存后，工作台才能显示它。

### 第一次就要配置 MCP 吗？

不需要。直接生成和复制小票都可以通过项目自带的 Python 命令入口操作。

MCP 是让 AI 助手直接调用项目工具的一种连接方式，熟悉基本流程后再接入即可。安装和配置说明见 [工作台指南中的“可选 MCP”](workbench/README.md#可选-mcp)；网页右上角的“MCP 接入”可以生成适合当前电脑的配置片段。
